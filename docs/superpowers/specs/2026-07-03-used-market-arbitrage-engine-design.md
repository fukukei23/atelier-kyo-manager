# 中古品 相場乖離検知エンジン（used-market-arbitrage-engine）設計書

> 作成日: 2026-07-03
> ステータス: ドラフト（ユーザーレビュー待ち）
> 前身プロジェクト: atelier-kyo-manager（BUYMA向け新品ブランド転売システム）
> 関連レビュー: GLM / MiniMax 両LLMによる方向性レビュー済み（両者「条件付き賛成」）

---

## 1. 背景と問題

atelier-kyo-manager は BUYMA 向けの新品ブランド品転売システムとして作り込まれた（Flask、価格スクレイピング、出品パイプライン、注文ステートマシン、LLM連携、テスト2,070件）。しかし新品ブランド品は、ネット仕入れ（FARFETCH / italist 等）では **法人卸・VIP買付・現地買付＋VAT還付組に仕入れ原価で構造的に勝てない**ことが判明し頓挫した（根拠: `30_RESEARCH/atelier-kyo/` の各調査）。eBay 等への横展開も同様に厳しい感触。

一方で、このシステムに詰まっている技術資産（監視・スクレイピング・ステルス・相場分析・LLM連携・状態管理）は、ネットビジネスの基本が凝縮されており、**別の土俵で活かせる**可能性が高い。

## 2. 目的と成功基準

- **目的**: 既存システム資産を「中古品の相場乖離検知エンジン」に転用し、副収入として **月3〜10万円の粗利**を現実的に狙う。
- **成功基準（Phase 1 到達判定）**: 実弾投入カテゴリで、手数料・送料込みの**実測純利益が月3万円以上**を2ヶ月連続で達成。
- **撤退基準**: Phase 0 で全候補カテゴリが数値閾値（§7）を下回った場合、実弾を投入せず事業モデル自体を見直す。

### 制約・前提（ユーザー確定事項）

- 資金: 50万円以上。有在庫OK。古物商許可: 取得済み/取得予定。
- 運用: **購入判断・検品・発送は人間**が行う（Botによる自動購入はしない）。システムは監視・候補抽出・査定・通知まで。
- スクレイピング規約リスク: **回避のための作り込みは行う**（既存ステルス資産を活用）。多重アカウント運用・法的グレーは運用者判断とし、設計上のリスク回避作り込みはステルス層に限定する。
- SaaS化: **本スコープ外（将来オプション）**。自分の成約実績・利益データが最強の営業材料になるため、実績を出した後の Phase 3 以降に棚上げ。

## 3. 核心仮説

1. **中古市場には新品ブランド品のような仕入れルートの構造壁がない**。個人出品者が相場を知らずに安値で出すため、「相場より安い出品を、早く・正確に見つける」情報戦で個人でも勝てる余地がある。
2. **個体差（状態・付属品）問題は、LLMを賢くして解くのではなく "精度が出ない案件は買わない" で回避できる**。同定・相場算出は機械的に確実にやり、状態抽出だけLLMに任せ、情報が不確実な案件は保守側（見送り）に倒す。
3. **どのカテゴリで戦うかは事前に決めず、データで淘汰する**。エンジンをカテゴリ非依存に作り、カテゴリ固有情報を設定ファイル化することで、実弾ゼロのペーパートレードで勝てるカテゴリを選別する。

> 両LLMレビューの留保: 「中古の相場乖離ツールには先行競合がおり、技術だけでは勝てない」「ペーパートレードでは "実際に買えたか（流動性）" が測れない」。→ §7 のハイブリッド検証と数値閾値で対処する。

## 4. 全体アーキテクチャ（既存資産の転用マップ）

エンジンは**カテゴリ非依存**。カテゴリごとに異なるのは設定ファイル（§6）だけ。

```
[監視ループ] → [同定] → [基準相場算出] → [状態抽出(LLM)] → [減額査定] → [判定] → [通知] → 人間が購入判断
```

## 5. 査定パイプライン（本エンジンの心臓部）

設計思想: **LLMに値付けさせない。LLMは「構造化抽出」だけ担当。値付けはルールベース。**

### Step 1: 同定（機械的・LLM不使用）
- 出品タイトル/説明から型番・モデル名を辞書＋正規表現で特定。`product_matching.py` の `extract_model_numbers()` と `NOISE_WORDS` を流用。
- **特定できなければ案件を捨てる**（あいまいな物は土俵に乗せない = 精度の源泉）。

### Step 2: 基準相場算出（機械的）
- 同一型番の直近成約価格（相場DB）から相場レンジ（中央値・下位/上位四分位）を算出。
- サンプル不足（例: 直近成約 < N件）の型番はスキップ（相場が信用できない）。

### Step 3: 状態・付属品の抽出（ここだけLLM）
- 出品説明文＋写真をLLMに渡す。**値段は聞かない**。以下を決められたJSON形式で抽出:
  - `state_grade`（カテゴリ定義のグレード）
  - `accessories`（付属品チェックリストに対する有無）
  - `defects`（難あり要素の列挙）
  - `extraction_confidence`（0.0〜1.0）
- 出力は JSON スキーマで強制し、パース失敗・低信頼度は Step 5 で見送りに倒す。

### Step 4: 減額査定（ルールベース）
- カテゴリ設定の減額ルールで基準相場を調整（例: 箱なし −5%、保証書なし −8%、カビ/クモリ −40%）。
- 地雷キーワード（ジャンク/訳あり/コピー品 等）該当は自動除外 or 大幅減額。

### Step 5: 判定と通知
- `期待利幅 = 調整後相場 − 出品価格 − 販売手数料 − 送料 − (必要なら)修理/清掃コスト`
- **利幅が閾値超え かつ `extraction_confidence` が閾値超え** の案件だけ人間に通知。
- 情報不足・状態不明・信頼度低は**保守側（見送り）**に倒す。

> 副次効果: 情報が構造化しやすいカテゴリほど査定精度が出て有利になり、Phase 0 の淘汰に「LLM査定が効くカテゴリ」を選ぶ淘汰圧が自然にかかる。

## 6. カテゴリ設定ファイル（ドメイン知識の外部化）

カテゴリごとに1ファイル（JSON/YAML）。エンジン本体は不変。

```yaml
category: used_camera_lens
sources:                      # 監視対象サイト（出品側）
  - name: mercari
    search_queries: [...]
  - name: yahoo_auction
    search_queries: [...]
price_reference_sources:      # 相場DBを埋めるための成約価格ソース
  - name: mercari_sold
  - name: yahoo_auction_closed
model_dictionary:             # 型番辞書・抽出パターン
  patterns: [...]
  aliases: {...}
state_grades:                 # 状態グレード定義
  - {id: mint, label: "新品同様", base_multiplier: 1.00}
  - {id: good, label: "美品",     base_multiplier: 0.90}
  - {id: fair, label: "並品",     base_multiplier: 0.75}
  - {id: junk, label: "難あり",   base_multiplier: 0.40}
accessories_checklist:        # 付属品と欠品時の減額率
  - {id: box,     label: "箱",     penalty: 0.05}
  - {id: warranty,label: "保証書", penalty: 0.08}
  - {id: hood,    label: "フード", penalty: 0.03}
defect_rules:                 # 難あり要素の減額率
  - {keyword: ["カビ","クモリ"], penalty: 0.40}
  - {keyword: ["チリ","ホコリ"], penalty: 0.05}
landmine_keywords:            # 自動除外/大幅減額
  - ["ジャンク","訳あり","コピー","レプリカ","保証書なし(高額品)"]
thresholds:
  min_profit_yen: 5000        # 通知する最低期待利幅
  min_confidence: 0.7         # 通知する最低抽出信頼度
  min_sold_samples: 5         # 相場算出に必要な最低成約サンプル
```

初期候補カテゴリ（Phase 0 で並行検証）:
1. 中古カメラ・レンズ（オールドレンズ含む）
2. トレカ（ポケカ/遊戯王 等）
3. レトロゲーム・ゲーム機
4. 中古オーディオ機器
5. ブランド小物（既存リサーチ資産の検証枠）

## 7. Phase 0: カテゴリ淘汰トーナメント（実弾ゼロ + ハイブリッド検証）

期間: 2〜4週間。候補4〜5カテゴリを**並行**でペーパートレードにかける。

### 記録する指標（案件ごと）
- 検知時刻・出品価格・調整後相場・期待利幅・抽出信頼度
- **検知から売切れ（or 出品消滅）までの経過時間**（＝人間の購入判断が間に合うか）
- 「もし通知直後に買っていたら」の仮想損益

### 淘汰の数値閾値（MiniMaxレビュー採用: 事前に固定し恣意性を排除）

カテゴリが Phase 1（実弾）へ進む条件（すべて満たす）:
- **仮想月間粗利 ≥ 3万円**（= 案件頻度 × 平均利幅 × 購入間に合い率）
- **購入間に合い率 ≥ 30%**（検知後、人間が現実的に反応できる時間内に在庫が残っていた割合）
- **有効サンプル ≥ 20件**（統計的に薄すぎる判断を排除）
- **平均抽出信頼度 ≥ 0.7**（査定が効くカテゴリか）

### ハイブリッド検証（GLMレビュー採用: 「本当に買えたか」の実測）

ペーパートレードだけでは流動性・送料/手数料の実態が測れない。そこで Phase 0 後半で、閾値上位2カテゴリに対し **超小口の実弾プローブ**（1件5,000〜10,000円 × 数件）を投入し、
- 検知した安値案件を**実際に購入できるか**（決済成立率）
- 実送料・実手数料・実際の状態（届いた現物 vs LLM査定）の乖離

を実測して、仮想損益の過大評価バイアスを補正する。

### 並行準備（実弾フェーズのボトルネック除去）
- 販路アカウント（メルカリ/ヤフオク/eBay 等）の評価を低額出品で先に育てておく（Phase 1 で「評価ゼロで売れない」を回避）。

## 8. Phase 1 以降

- **Phase 1**: 実測1位カテゴリに小口実弾投入（1件1〜3万円 × 10件〜）。2位カテゴリはペーパートレード継続（保険）。資金回転試算（下記）で必要在庫件数・再投資サイクルを管理。
- **Phase 2**: 回転が確認できたら資金増額 + 販路追加（eBay 輸出: 日本の中古品 → 海外）を検討。
- **Phase 3（スコープ外・将来）**: 自分の成約実績を土台に、検知エンジンのSaaS/BOT提供を検討。

### 資金回転試算（GLMの資金効率懸念への回答・仕様に明記）
月間粗利目標 = 平均利幅 × 月間成約件数。月間成約件数 = (投下資金 ÷ 平均仕入単価) × (30 ÷ 平均回転日数)。
→ 目標月3〜10万を満たす「平均利幅 × 回転日数 × 必要資金」の組合せを Phase 0 実測値で逆算し、Phase 1 の投入設計に反映する。

## 9. リスクと対処

| リスク | 深刻度 | 対処 |
|---|---|---|
| ペーパートレードの過大評価（買えない案件を利益計上） | 高 | §7 ハイブリッド検証（超小口実弾プローブ）で実測補正 |
| LLM査定が個体差で外れる | 高 | §5 の「抽出専任・不明は見送り」設計。§7 で現物 vs 査定の乖離を実測 |
| 先行競合ツールに検知速度で負ける | 中 | 購入間に合い率を淘汰指標に組込み。負けるカテゴリは自動脱落 |
| 偽物・コピー品（トレカ/ゲーム/ブランド） | 中 | `landmine_keywords` で自動除外 + 人間の検品を必須工程に |
| 販路アカウントBAN | 中 | 運用者判断（設計上は考慮外の方針）。販路分散・アカウント事前育成で緩和 |
| サイトDOM変更でスクレイパー破損 | 中 | 既存の自己修復セレクタ資産を流用 |

## 10. スコープ外（YAGNI）

- 自動購入（Bot決済）— 規約/運用方針により人間が実行。
- SaaS/BOT 販売 — Phase 3 以降。
- 新品ブランド品仕入れ — 頓挫済みにつき対象外。
- 多重アカウント自動生成 — 運用者手動。設計対象はステルス層のみ。
