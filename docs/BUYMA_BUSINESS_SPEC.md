## 1. 概要

### 1.1 ツールの目的

BUYMA無在庫転売管理ツールは、BUYMAプラットフォーム上でパーソナルショッパー（出品者）が行う無在庫転売ビジネスの運用を効率化・自動化し、月収30万円達成に向けた持続可能なビジネス基盤を構築する。

### 1.2 対象ユーザー

| ユーザー像 | 説明 |
|-----------|------|
| パーソナルショッパー | BUYMAで出品を行う個人・小規模チーム |
| リーダー型ショッパー | 複数外注を活用したスケール型運用 |
| 副業勢 | 本業を持ちながらBUYMAで副収入を狙う層 |

### 1.3 プラットフォーム概要

| 項目 | 数値 |
|------|------|
| 会員数 | 1,200万人 |
| ショッパー数 | 22.5万人 |
| 取扱ブランド | 1.8万 |
| 取扱アイテム | 638万点以上 |

### 1.4 導入効果目標

- 月次出品目標（600品）の進捗可視化による達成率向上
- 18日ルール遵守率100%
- 平均利益率10%以上維持
- パートナー応答速度30分以内

## 2. ビジネスルール

### 2.1 BUYMAプラットフォームルール

#### 2.1.1 禁止買付先

| 区分 | 禁止 | 許可 |
|------|------|------|
| 国内 | 公式サイト（エルメス・ヴィトン等）、メルカリ | 店舗購入のみ |
| 海外 | - | 店舗 + オンライン購入可 |

> **重要:** アンダーバリュー（過少申告）は関税違反のため禁止

#### 2.1.2 発送期限ルール

```
注文日 ────── 18日 ────── 強制キャンセル
    │
    └─ 延長申請可（決済方法により期限が異なる）
```

| 決済方法 | 延長期限 | 備考 |
|---------|---------|------|
| クレジットカード / 楽天Pay | 45日 | 最も柔軟な対応が可能 |
| d払い / au Pay / ペイディ | 25日 | 中程度の猶予 |
| 銀行振込 / コンビニ / PayPay / Amazon Pay | 90日 | 最も長い猶予 |

#### 2.1.3 アカウント管理

- **外部委託:** 公認。ただし全ての責任はアカウント所有者に帰属
- **リスク:** 委託先によるルール違反も所有者が罰則対象
- **禁止:** 過去にBUYMA利用制限を受けたユーザーへの業務委託は、自身のアカウントも停止の可能性あり

### 2.2 手数料体系

#### 2.2.1 成約手数料（出品者負担）

| 出品区分 | 手数料率（税込） |
|---------|----------------|
| 国内ショッパー | 7.7% |
| 海外ショッパー | 5.5% |

#### 2.2.2 その他の手数料

| 項目 | 料率 | 負担者 |
|------|------|--------|
| 決済手数料 | 3.6% | 購入者 |
| 安心プラス | 1.47%（税込）、2万円以下は一律293円 | 購入者（任意） |
| 振込手数料 | 220円〜 | 出品者（楽天銀行推奨） |

#### 2.2.3 手数料計算例

```
【国内販売 販売価格50,000円の場合】

売上金額:         ¥50,000
─ 成約手数料(7.7%): ¥3,850
─ 振込手数料:       ¥220
─────────────────────────
実受領額:         ¥45,930

利益計算:
利益 = 販売価格 - 仕入原価 - 成約手数料 - 振込手数料
     = ¥50,000 - ¥40,000 - ¥3,850 - ¥220
     = ¥5,930（利益率 11.9%）
```

### 2.3 キャッシュフロー

| 仕入れ区分 | 平均着金日数 | 備考 |
|-----------|-------------|------|
| 国内仕入れ | 約15日 | 購入者受取後 |
| 海外仕入れ | 20〜30日 | 国際輸送含む |

> **前提:** 購入者の受け取り処理が入金の絶対要件。受け取り処理が遅れると入金も遅延。

### 2.4 ブランド階層

| Tier | ブランド例 | 利益/取引 | 特記事項 |
|------|-----------|----------|---------|
| **ハイブランド** | シャネル、エルメス、ヴィトン | 数万〜数十万円 | ヴィトンは初期規制あり |
| **ミドルブランド** | グッチ、プラダ、ナイキ | 数千〜数万円 | 扱いやすい |
| **ロングテール** | その他 | 〜数千円 | 回転率重視 |

**ヴィトン規制:** 初期は出品不可。実績を積むことで解除。BUYMAからの連絡は来ないため自分で確認が必要。

### 2.5 運営5ステップ（月収30万ロードマップ）

#### Step 1: 基盤構築（1-2ヶ月目）

- アカウント設定（アイコン・ヘッダー・プロフィール整備）
- ニックネーム（ショップ名）は後から変更不可なので慎重に決定
- 外注化体制構築（出品外注：1品40-50円、クラウドワークス活用）
- 買付パートナー複数確保

#### Step 2: アクセス数増加（3-4ヶ月目）

| KPI | 目標値 |
|-----|--------|
| 日次出品数 | 20品 |
| 月次出品数 | 600品 |

- 新着順で上位表示されるため継続出品が重要
- メイン画像に商品特徴・アピールポイントを掲載
- 人気上位ランクイン要素: 販売実績・問い合わせ数・お気に入り数・アクセス数

#### Step 3: 買付力向上（4-5ヶ月目）

- ハイブランド担当者確保（仕入れ・取り寄せ・郵送で有利）
- 迅速なレスポンス（在庫確認等）で競合への顧客流出防止
- パートナーレスポンス遅延時は契約見直しも検討

#### Step 4: 高利益商品理解（5-6ヶ月目）

- 希少性の高いハイブランド商品を扱う
- 利益の大きい商品・カテゴリーの理解
- 最新情報の常にインプット・アウトプット、最速で行動

#### Step 5: リピーター構築（6ヶ月目以降）

- 丁寧で迅速な問い合わせ対応
- クーポン発行で再来訪動機を作る
- 希少価値の高い商品の販売実績で信頼構築

## 3. 機能要件

### 3.1 優先度定義

| 優先度 | 意味 | フェーズ |
|--------|------|---------|
| **P0** | 即実装必須 | 第1フェーズ |
| **P1** | 早期実装 | 第2フェーズ |
| **P2** | 拡張機能 | 第3フェーズ |

### 3.2 P0: 即実装（Must Have）

#### F01: 禁制品買付先チェックシステム

- 商品ごとに買付先が禁止対象か自動判定
- 国内→店舗のみ許可、公式サイト/メルカリ禁止
- 海外→店舗+オンライン許可
- 商品登録時・買付先選択時にリアルタイム警告表示

#### F02: 18日ルール + 決済別延長期限ダッシュボード

- 各注文の発送期限を可視化管理
- 注文日・期限日・残日数・延長可否を一覧表示
- 決済方法別の最大延長期限を自動算出

**期限警告レベル:**

| 残日数 | 表示 | アクション |
|--------|------|-----------|
| 7日以上 | 緑（正常） | なし |
| 3-6日 | 黄（注意） | 進捗確認 |
| 1-2日 | 赤（警告） | 延長申請または発送催促 |
| 0日以下 | 緊急（点滅） | 即時対応 |

#### F03: パートナー管理

| 管理項目 | 説明 | 重要度 |
|---------|------|--------|
| レスポンス速度 | 平均応答時間（分） | 高 |
| 信頼スコア | 実績ベースの信頼度（0-100%） | 高 |
| 対応地域 | 買付可能エリア | 中 |
| 得意ブランド | 専門分野 | 中 |
| 優先度 | high/medium/low | 中 |

**対応地域マスタ:**
- 国内: 東京・大阪・名古屋・愛知・沖縄
- 海外: ユーロ圏・米国・香港・豪州・中国

### 3.3 P1: 第2フェーズ（Should Have）

#### F04: 品出し進捗トラッカー

- 日次/月次の出品進捗をリアルタイム追跡
- 日次目標: 20品 / 月次目標: 600品
- 7日間平均、前月比較のトレンド表示

#### F05: キャッシュフロー予測

- 月次売上予測
- 入金予定額（今月中の確定着金）
- 未着金残高
- 着金予測: 国内=注文日+15日、海外=注文日+25日（中央値）

#### F06: ブランド階層別利益率ダッシュボード

| Tier | 平均利益率 | 推奨アクション |
|------|-----------|---------------|
| ハイブランド | 15-25% | 規制解除後強化 |
| ミドルブランド | 10-15% | 主力として継続 |
| ロングテール | 5-8% | 回転率重視 |

### 3.4 P2: 第3フェーズ（Nice to Have）

#### F07: 人気度トラッキング

加重スコア計算式:

```
popularity_score = (sales_normalized × 0.4) + (inquiries_normalized × 0.3)
                 + (favorites_normalized × 0.2) + (views_normalized × 0.1)
```

#### F08: 買付先地域最適化レコメンド

商品の最安・最速買付先を推奨（ブランド×地域の過去実績に基づく）

#### F09: リピーター管理

- 顧客別購入履歴・お気に入り・購買パターン
- クーポン発行機能
- 新商品案内の一括送信

## 5. アラート・通知システム

| ID | アラート名 | トリガー条件 | 重要度 |
|----|-----------|-------------|--------|
| A-01 | 18日ルール接近 | deadline - now < 3日 | 高 |
| A-02 | 18日ルール超過危機 | deadline - now < 1日 | 緊急 |
| A-03 | 延長期限接近 | extension_deadline - now < 3日 | 中 |
| A-04 | 延長期限超過 | now > extension_deadline | 緊急 |
| A-05 | 禁制品買付先指定 | prohibited_source選択時 | 緊急 |
| A-06 | 利益率低下 | profit_rate < 5% | 中 |
| A-07 | 日次品出し未達 | 24時までに20品未達 | 低 |
| A-08 | 月次品出し進捗遅延 | 日次ペース不足（残り日数で達成不可） | 中 |
| A-09 | パートナー応答遅延 | response_time > 30分（ハイブランド注文） | 低 |

## 6. 価格計算ロジック

### 6.1 利益計算式

```
commission_rate = (sourceType == 'domestic') ? 0.077 : 0.055
fees = sellingPrice × commission_rate + transferFee(220)
customsDuty = (sourceType == 'overseas') ? calcCustomsDuty(cifPrice, category) : 0
profit = sellingPrice - purchaseCost - fees - customsDuty
profitRate = profit / sellingPrice × 100
```

### 6.2 決済方法別延長期限計算

```
extensionMap = {
  'credit_card': 45,
  'rakuten_pay': 45,
  'd_pay': 25,
  'au_pay': 25,
  'paidy': 25,
  'bank_transfer': 90,
  'convenience': 90,
  'paypay': 90,
  'amazon_pay': 90,
}
extensionDeadline = orderDate + extensionMap[paymentMethod]
```

### 6.3 入金予定日計算

```
expectedPaymentDate = orderDate + (
  sourceType == 'domestic' ? 15 :
  sourceType == 'overseas' ? 25 :  // 中央値
  0
)
```

## 7. 対応地域マスタ

### 7.1 国内

| 地域 | 特徴 |
|------|------|
| 東京 | 旗艦店多数、ハイブランドの品揃え豊富 |
| 大阪 | 関西エリアの拠点 |
| 名古屋/愛知 | 中部エリアの拠点 |

### 7.2 海外

| 地域 | 通貨 | 特徴 |
|------|------|------|
| ユーロ圏（仏・伊・独） | EUR | ハイブランドの本拠地、EUR/JPYレート有利な場合あり |
| 米国 | USD | ナイキ等の本国、セール頻度高い |
| 香港 | HKD | 関税なし、ハイブランド品揃え良好 |
| 豪州 | AUD | 地域限定アイテムあり |
| 中国 | CNY | 一部ブランドの国内価格が安い場合あり |
