# 1ページ目｜表紙・重要注意（確定版）

# BUYMA無在庫
# 半自動 出品準備補助ツール

ローカル実行型／CSV生成・利益確認・説明文下書き

## 本ツールについて（最重要）

本ツールは、
BUYMA無在庫出品における「出品準備作業」を標準化・簡略化するための補助ツールです。

以下の行為は 一切行いません。

- BUYMAへのログイン
- 商品の自動出品
- 在庫監視・価格自動変更
- アカウント操作・出品代行

出品の最終判断・操作は、すべて利用者自身が行います。

## このツールの位置づけ

- 本ツールは 出品準備の補助です
- 利益・可否の判断を代行するものではありません
- 生成される内容は 参考情報・下書きに留まります
- BUYMAの利用規約を遵守する責任は、
  すべて利用者自身にあります。

## 想定利用者

- BUYMA無在庫出品を行っている、または検討している方
- 出品準備を「毎回ゼロから考える」状態から脱却したい方
- 自動化よりも 安全性・再現性・判断のしやすさを重視する方

## ご注意（必ずお読みください）

- 本ツールは 利益を保証するものではありません
- BUYMAからの警告・停止・アカウント制限等について
  開発者は責任を負いません
- 本ツールの利用によって生じたいかなる損害についても、
  最終的な責任は利用者に帰属します

# 2ページ目｜できること／できないこと（線引きページ・確定版）

## このツールで「できること」

本ツールは、BUYMA無在庫出品における
出品準備作業を効率化・標準化するための補助ツールです。

具体的には、以下のことができます。

### 1. 出品用CSVの生成

- 商品情報CSVをもとに
  BUYMA出品用CSVを生成します
- CSVは「最終提出用」ではなく
  確認・調整前提の中間成果物です

### 2. 利益計算・判断補助

- 入力された仕入価格・送料・為替・想定販売価格から
  利益額・利益率を算出します
- 利益が未確定な場合は
  partial（未確定）として明示されます
- 利益判断は あくまで補助であり、最終判断は利用者が行います

### 3. 説明文の下書き生成（任意）

- OpenAI APIを利用し
  商品説明文の下書きを生成します
- 生成結果は 必ず人が確認・修正してください
- 規約回避・誇張・断定表現は 禁止です

### 4. 画像の最低限整形

- 画像サイズの調整
- ファイル名の整理
- ※ 演出・加工・誇張は行いません

## このツールで「できないこと」（重要）

以下の行為は 設計上、明確に除外されています。

### ❌ 出品操作に関すること

- BUYMAへのログイン
- 商品の自動出品
- 出品情報の直接登録
- 出品代行

### ❌ アカウント・監視系

- 在庫自動監視
- 価格の自動変更
- アカウント情報の取得・保存・操作

### ❌ 自動化・回避行為

- ブラウザ自動操作
- スクレイピング強化
- 規約回避を目的とした挙動

## なぜ「できないこと」があるのか

これらを含めると、以下のリスクが急激に高まります。

- BUYMA規約違反
- アカウント停止（BAN）
- 誤操作による損害
- 情報漏えい

本ツールは
「安全に・長く使える」ことを最優先に設計されています。

## 本ツールの立ち位置（再確認）

- 出品準備を 毎回ゼロから考えないための道具
- 判断を 速く・整理しやすくするための補助
- 出品行為そのものを 代行・自動化しない

# 3ページ目｜全体フロー（1商品分の出品準備）

## 出品準備の全体像

本ツールを使った 1商品分の出品準備は、
以下の 6ステップで完了します。

※ このフローは 毎回同じ順序で実行することを前提に設計されています。

## Step 1｜商品情報CSVを用意する

出品したい商品の情報を
指定フォーマットのCSVに入力します

必須項目・任意項目は後述します

この時点では、
BUYMAの管理画面を開く必要はありません。

## Step 2｜コマンドを1回実行する

ターミナル（コマンドプロンプト）で
以下のように 1コマンドを実行します。

```
python -m app.utils.sourcing_csv_runner --csv 入力CSV.csv --row 0
```

- `--csv`：入力CSVのパス
- `--row`：処理したい行番号（0始まり）

## Step 3｜出力ファイルが生成される

コマンド実行後、以下のファイルが生成されます。

- 出品用CSV
- 利益計算結果（profitability）
- Tier判定結果（tier_judgement）
- 実行ログ

これらは 自動生成される中間成果物です。

## Step 4｜利益・Tierを確認する

生成された結果を確認し、以下を判断します。

- 利益額は許容範囲か
- 利益率は問題ないか
- Tier（A/B/C）は想定どおりか

※ 不足情報がある場合は
partial（未確定）として明示されます。

## Step 5｜説明文の下書きを確認・修正する

説明文下書きが生成されている場合：

- 内容を必ず人が確認
- 表現の誇張・断定がないかを確認
- BUYMA規約に反しないかを確認

そのまま使うことは推奨されません。

## Step 6｜人が最終判断し、BUYMAへ提出する

最終的に：

- 出品するかどうか
- 価格をどうするか
- 説明文・画像をどう調整するか

これらは すべて利用者自身が判断し、
BUYMA管理画面から 手動で出品します。

## 本フローの設計意図

- 出品準備を 毎回ゼロから考えない
- 判断ポイントを 見える化する
- 自動化による事故を 構造的に避ける

本ツールは
**「考える負担を減らし、判断は残す」**ための道具です。

# 6ページ目｜入力CSVの作り方①（必須項目）

## 入力CSVの役割

入力CSVは、
1商品分の出品準備情報をまとめて記載するための入力ファイルです。

本ツールは、このCSVをもとに：

- 出品用CSVの生成
- 利益計算
- Tier判定
- 説明文下書き生成（任意）

を行います。

## CSVの基本ルール

- ファイル形式：CSV（カンマ区切り）
- 文字コード：UTF-8
- 1行＝1商品
- ヘッダー行は必須

## 必須項目一覧

以下の項目は 必須です。
1つでも欠けている場合、処理は partial（未確定） になります。

### 1. 商品名

- 出品時の基準となる商品名
- BUYMA掲載用に最終調整する前提の仮名称で問題ありません

### 2. 仕入価格

- 仕入れにかかる 商品本体価格
- 通貨単位は明示的に指定します

### 3. 送料

- 仕入れ先から購入者へ発送する際の送料
- 不明な場合は空欄でも可（その場合は partial 扱い）

### 4. 想定販売価格

- BUYMAでの 想定販売価格
- 実際に出品する価格とは異なっても構いません

### 5. 為替レート

- 利益計算に使用する為替レート
- 自動取得は行いません
- 利用者が入力した値をそのまま使用します

## 入力例（イメージ）

```
product_name,purchase_price,shipping_cost,sell_price,exchange_rate
Sample Product,80000,5000,120000,150
```

※ 実際の項目名・順序は、
tests/fixtures/ のサンプルCSVを必ず参照してください。

## なぜ「必須項目」があるのか

- 利益計算の前提条件を揃えるため
- 判断材料を 曖昧にしないため
- 無理な自動補完による事故を防ぐため

本ツールは
不足情報を無理に補わず、明示的に「未確定」とします。

## 注意点（重要）

- 数値は 半角数字で入力してください
- 通貨単位の混在に注意してください
- 意味が分からない項目は 空欄のままで構いません

# 7ページ目｜入力CSVの作り方②（任意項目・partialの考え方）

## 任意項目について

入力CSVには、
必須ではないが、判断精度を上げるための任意項目があります。

これらは未入力でも処理は実行されます。

## 主な任意項目の例

### 1. 関税・輸入手数料

- 商品にかかる可能性のある関税・手数料
- 不明な場合は 空欄で問題ありません

### 2. 梱包・諸経費

- 梱包材費、手数料など
- 実費が分からない場合は未入力で構いません

### 3. 原価メモ・補足情報

- 判断時に自分が分かればよいメモ
- 出力結果には直接影響しません

※ 実際に使用できる任意項目は、
tests/fixtures/ 内のサンプルCSVを基準としてください。

## partial（未確定）とは何か

partial とは、
利益計算・判定に必要な情報が一部不足している状態を指します。

## partial になる主なケース

- 送料が未入力
- 関税・手数料が未確定
- 為替レートが未入力

この場合でも、
処理自体は中断されません。

## partial 時の出力の考え方

- 利益額・利益率は null または未確定表示
- 代わりに 上限値・参考値が提示される場合があります
- Tier は 仮判定として表示されます

## なぜ partial を許容するのか

- 実務では、最初から全情報が揃わないことが多いため
- 無理に推定すると、判断を誤るため
- 「分からない」を 明示する方が安全なため

本ツールは
曖昧さを隠さず、判断材料として提示します。

## partial 状態でやるべきこと

- 不足項目を確認する
- 仕入れ先・配送条件を再確認する
- 必要に応じて CSV を修正し、再実行する

## 再実行について

- 入力CSVを修正後、
  同じコマンドを再度実行してください
- 上書き・再生成は問題ありません

# 8ページ目｜実行コマンドの詳細（row指定・複数商品の考え方）

## 基本となる実行コマンド

本ツールは、
1回のコマンド実行で、1商品分の出品準備を行います。

基本形は以下です。

```
python -m app.utils.sourcing_csv_runner --csv 入力CSV.csv --row 0
```

## 各オプションの意味

### --csv

- 処理対象となる 入力CSVファイルのパス
- 相対パス・絶対パスのどちらも使用できます

例：

```
--csv ./data/input_products.csv
```

### --row

- 入力CSV内の 処理対象行番号
- 0始まりです（1行目のデータは 0）

例：

```
--row 0   # 1行目の商品
--row 1   # 2行目の商品
```

## なぜ row 指定があるのか

- 1商品ずつ 判断・確認しながら進めるため
- 大量一括処理による誤出品を防ぐため
- 利益や条件を 個別に精査するため

本ツールは
**「速さより安全性」**を優先しています。

## 複数商品を扱う場合の考え方

### 推奨手順

- 入力CSVに複数商品を記載
- --row を変えて 1商品ずつ実行
- 各商品ごとに結果を確認

例：

```
python -m app.utils.sourcing_csv_runner --csv products.csv --row 0
python -m app.utils.sourcing_csv_runner --csv products.csv --row 1
```

### バッチ処理について（補足）

- 複数商品を一括で処理する仕組みも存在します
- ただし、商品版では常用を推奨しません

理由：

- 判断が追いつかない
- エラーや partial を見落としやすい
- 実務事故につながりやすい

## 実行時の注意点

- CSVは 保存してから実行してください
- 実行中にCSVを編集しないでください
- エラーが出た場合は ログを確認してください

## よくあるミス

- --row を 1始まりと誤解する
- CSVのパス指定ミス
- CSVを開いたまま実行する（ロック）

# 9ページ目｜出力結果の読み方①（出品用CSV・profitability）

## 出力結果について

コマンドを実行すると、
出品準備に必要な複数の出力ファイルが生成されます。

これらはすべて
**「最終提出前の確認用成果物」**です。

## 出品用CSV

### 役割

- BUYMA出品画面にアップロードするためのCSV
- 必要項目が自動的に整形された状態で出力されます

### 注意点（重要）

- そのまま提出することは推奨されません
- 必ず内容を確認・調整してください
- 商品名・説明文・価格は 最終確認必須です

### 確認すべきポイント

- 商品名に誤解を招く表現がないか
- カテゴリ・属性が適切か
- 価格が想定どおりか

## profitability（利益計算結果）

### 役割

- 利益額・利益率の判断材料
- 出品可否を考えるための補助情報

### 主な項目の見方

#### profit
- 実質的な利益額
- ※ partial の場合は null になります

#### profit_rate
- 利益率
- ※ profit が未確定の場合は null

#### status

- complete：必要情報が揃っている
- partial：一部情報が不足している

### partial 表示の意味

- 計算不能ではありません
- 判断材料が不足している状態です
- 無理に数値を信じないでください

## この出力の使い方

- 出品するかどうかの 一次判断
- 条件を見直すべきかの 検討材料
- 利益が薄い商品の 早期除外

本ツールは
**「決断を代行せず、判断を整理する」**ための設計です。

## やってはいけないこと

- profit / profit_rate を 鵜呑みにする
- partial 状態のまま出品を進める
- 出力CSVを無確認で提出する

# 10ページ目｜出力結果の読み方②（Tier判定・ログ）

## Tier判定とは何か

Tier判定は、
**利益条件・不確実性を踏まえた「判断の目安」**を示すものです。

本ツールでは、
各商品に対して A / B / C のTierを付与します。

## 各Tierの意味

### Tier A

- 利益条件が明確
- 数値が安定している
- 出品候補として 前向きに検討可能

※ それでも最終判断は人が行います。

### Tier B

- 利益は出る可能性がある
- 条件次第で変動する余地がある
- 要確認・要再計算

### Tier C

- 利益が薄い、または不確実性が高い
- 情報不足（partial）を含む場合が多い
- 慎重判断が必要

※ Tier C ＝ 即NG ではありません。

## Tier判定の使い方

- 出品可否を 機械的に決めるためのものではありません
- 検討優先度を整理するための指標です
- 判断を 速く・一貫させるために使います

## ログファイルについて

### ログの役割

- 実行時の処理内容・エラー情報を記録
- トラブル時の確認材料

### ログの保存先

- docs/reports/ 配下に保存されます

### ログを確認すべきケース

- エラーが発生した場合
- 出力結果が想定と異なる場合
- partial の理由を確認したい場合

### ログの見方（基本）

- 処理開始／終了の時刻
- 読み込まれたCSVの行番号
- 不足項目・警告メッセージ

※ 詳細な解析は不要です。
エラー内容を把握できれば十分です。

## 判断に迷ったときの考え方
