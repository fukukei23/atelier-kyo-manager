# BUYMA転売 セッション進行テンプレート

> セッション開始時にこのファイルを開き、フェーズ順に進める。
> 人間とAI（Claude Code）の共有プロセス。迷ったらここに戻る。

---

## Phase 1: 現状把握（5分）

- [ ] `docs/経営者判断.md` の内容確認
  - 手数料・関税率・利益閾値・ブランド戦略に変更ないか
- [ ] `docs/ロードマップ.md` の現在フェーズ確認
- [ ] バックログ確認（SSOT `00_SYSTEM/バックログ.md`）
- [ ] 前回セッションのハンドオフ確認（`~/.claude/state/handoff.md`）

---

## Phase 2: ゴール設定（5分）

- [ ] 今回のメインゴールを1個決定
  - 「ビジネス運用」or「開発」or「両方」のどれをメインにするか
- [ ] サブゴールがあれば0-2個追加
- [ ] ビジネス判断が必要な項目をリストアップ
  - 例: 「BUYMA登録やる？」「商品数どれくらい？」「どのブランドから？」
- [ ] ゴールをSSOT日記に宣言として記録

---

## Phase 3: 実行（30-90分）

### サブレーンA: ビジネス運用

- [ ] BUYMAセラー登録進捗確認
- [ ] Buyandship口座状況確認
- [ ] 仕入れ先（EU公式サイト等）の価格チェック
- [ ] 出品候補の選定・利益計算
- [ ] 実際の出品作業

### サブレーンB: 開発

- [ ] `CLAUDE.md` Layer A（経営者判断・要件定義）を読込
- [ ] 機能実装 or バグ修正
- [ ] テスト実行（`python3 -m pytest`）
- [ ] スクレイパーの動作確認（新ブランド追加等）

---

## Phase 4: 記録（10分）

- [ ] `docs/変更履歴.md` 更新（開発した場合）
- [ ] SSOT日記（`10_DAILY/YYYY-MM-DD.md`）にセッションログ追記
- [ ] `01_DECISIONS/atelier-kyo-manager/` に判断記録（重要な決定があれば）
- [ ] バックログ更新（完了・追加・保留）

---

## Phase 5: 次回引き継ぎ（5分）

- [ ] 次回やることを3行程度でメモ
- [ ] 保留項目と理由をバックログに記録
- [ ] 未解決問題があれば明記

---

## 使い方

### セッション開始時

```
「BUYMA転売セッション進める」
または
「セッション進行テンプレートに従って進める」
```

Claude Codeがこのテンプレートを読み込み、Phase 1から順にガイドする。

### セッション中

- 各フェーズのチェック項目を1つずつ確認
- ユーザーが「スキップ」と言った項目は飛ばしてOK
- Phase 3のサブレーンは、その回のゴールに合わせてA/B/両方から選ぶ

### 短いセッションの場合

Phase 2-3-4を圧縮して15-30分でも使える:

```
Phase 1: 現状確認（3分）
Phase 2-3: ゴール設定→即実行（10-20分）
Phase 4-5: 記録→引き継ぎ（5分）
```
