## 1. 概要

### 1.1 ツールの目的

**Atelier Kyo Manager** は、BUYMAプラットフォーム上での無在庫転売ビジネス（ショップ名: Atelier Kyo）の運用を一括管理・半自動化・効率化し、月収30万円達成に向けた持続可能なビジネス基盤を構築する。

### 1.2 設計方針

| 方針 | 内容 |
|------|------|
| **半自動化** | BUYMAに公式APIがないため、完全自動化は規約違反リスクあり。手動作業を補完する設計（CSV出力、フォーム自動入力、テンプレート生成）を基本とする |
| **スクレイピング活用** | Selenium + selenium-stealth で仕入れ元サイトの価格・在庫チェックを実現（BUYMA本体へのスクレイピングは最小限） |
| **段階的拡張** | P0（即実装）→ P1 → P2 の3フェーズで開発 |

### 1.3 対象ユーザー

| ユーザー像 | 説明 |
|-----------|------|
| Atelier Kyo 運営者 | 自身（単一ユーザー専用Webアプリ） |
| 外注出品担当者 | クラウドワークス経由で出品作業を委託（将来アクセス権付与） |
| 買付パートナー | 国内外の買付担当者（パートナー管理機能で一元管理） |

### 1.4 プラットフォーム概要

| 項目 | 数値 |

| プラットフォーム | BUYMA（株式会社エンダースキーマ） |

### 1.5 導入効果目標

## 2. BUYMAビジネスルール

### 2.1 プラットフォーム制約（超重要）

> **BUYMAには公式APIが存在しない。** これが本ツールの設計に与える影響：
> - 出品登録 → CSV出力 → 手動 or 半自動入力（AutoFiller補助）
> - 注文取得 → メール通知ベース or 手動入力
> - 価格変更 → 手動 or Selenium（規約リスクあり）
> - 在庫確認 → 仕入れ元サイトのみスクレイピング可能

### 2.2 禁止買付先

| 区分 | 禁止 | 許可 |
|------|------|------|
| 国内 | 公式サイト（エルメス・ヴィトン等）、メルカリ | 店舗購入のみ |
| 海外 | - | 店舗 + オンライン購入可 |

> **重要:** アンダーバリュー（過少申告）は関税違反のため禁止

### 2.3 発送期限ルール

```
注文日 ────── 18日 ────── 強制キャンセル
    │
    └─ 延長申請可（決済方法により期限が異なる）
```

| 決済方法 | 延長期限 | 備考 |
|---------|---------|------|
| クレジットカード / 楽天Pay | 45日 | 最も柔軟な対応が可能 |
| d払い / au Pay / ペイディ | 25日 | 中程度の猶予 |
| 銀行振込 / コンビニ / PayPay / Amazon Pay | 90日 | 最も長い猶予 |

#### 2.3.1 アカウント管理

- **外部委託:** 公認（出品外注: 1品40-50円、クラウドワークス活用）
- **リスク:** 委託先によるルール違反も所有者が罰則対象
- **禁止:** 過去にBUYMA利用制限を受けたユーザーへの業務委託は、自身のアカウントも停止の可能性あり
- **ニックネーム（ショップ名）:** 後から変更不可

### 2.4 手数料体系

#### 2.4.1 成約手数料（出品者負担）

| 出品区分 | 手数料率（税込） |
|---------|----------------|
| 国内ショッパー | 7.7% |
| 海外ショッパー | 5.5% |

#### 2.4.2 その他の手数料

| 項目 | 料率 | 負担者 |
|------|------|--------|
| 決済手数料 | 3.6% | 購入者 |
| 安心プラス | 1.47%（税込）、2万円以下は一律293円 | 購入者（任意） |
| 振込手数料 | 220円〜 | 出品者（楽天銀行推奨） |

#### 2.4.3 手数料計算例

```
【国内販売 販売価格50,000円の場合】

売上金額:         ¥50,000
─ 成約手数料(7.7%): ¥3,850
─ 振込手数料:       ¥220
─────────────────────────
実受領額:         ¥45,930

利益計算:
利益 = 販売価格 - 仕入原価 - 成約手数料 - 振込手数料
     = ¥50,000 - ¥40,000 - ¥3,850 - ¥220
     = ¥5,930（利益率 11.9%）
```

### 2.5 キャッシュフロー

| 仕入れ区分 | 平均着金日数 | 備考 |
|-----------|-------------|------|
| 国内仕入れ | 約15日 | 購入者受取後 |
| 海外仕入れ | 20〜30日 | 国際輸送含む |

> **前提:** 購入者の受け取り処理が入金の絶対要件。受け取り処理が遅れると入金も遅延。

### 2.6 ブランド階層

| Tier | ブランド例 | 利益/取引 | 特記事項 |
|------|-----------|----------|---------|
| **ハイブランド** | シャネル、エルメス、ヴィトン | 数万〜数十万円 | ヴィトンは初期規制あり |
| **ミドルブランド** | グッチ、プラダ、ナイキ | 数千〜数万円 | 扱いやすい |
| **ロングテール** | その他 | 〜数千円 | 回転率重視 |

**ヴィトン規制:** 初期は出品不可。実績を積むことで解除。BUYMAからの連絡は来ないため自分で確認が必要。

### 2.7 運営5ステップ（月収30万ロードマップ）

#### Step 1: 基盤構築（1-2ヶ月目）

- アカウント設定（アイコン・ヘッダー・プロフィール整備）
- ニックネーム（ショップ名）は後から変更不可なので慎重に決定
- 外注化体制構築（出品外注：1品40-50円、クラウドワークス活用）
- 買付パートナー複数確保

#### Step 2: アクセス数増加（3-4ヶ月目）

| KPI | 目標値 |
|-----|--------|
| 日次出品数 | 20品 |
| 月次出品数 | 600品 |

- 新着順で上位表示されるため継続出品が重要
- メイン画像に商品特徴・アピールポイントを掲載
- 人気上位ランクイン要素: 販売実績・問い合わせ数・お気に入り数・アクセス数

#### Step 3: 買付力向上（4-5ヶ月目）

- ハイブランド担当者確保（仕入れ・取り寄せ・郵送で有利）
- 迅速なレスポンス（在庫確認等）で競合への顧客流出防止
- パートナーレスポンス遅延時は契約見直しも検討

#### Step 4: 高利益商品理解（5-6ヶ月目）

- 希少性の高いハイブランド商品を扱う
- 利益の大きい商品・カテゴリーの理解
- 最新情報の常にインプット・アウトプット、最速で行動

#### Step 5: リピーター構築（6ヶ月目以降）

- 丁寧で迅速な問い合わせ対応
- クーポン発行で再来訪動機を作る
- 希少価値の高い商品の販売実績で信頼構築

## 3. 機能要件

### 3.1 優先度定義

| 優先度 | 意味 | フェーズ |
|--------|------|---------|
| **P0** | 即実装必須 | 第1フェーズ |
| **P1** | 早期実装 | 第2フェーズ |
| **P2** | 拡張機能 | 第3フェーズ |

### 3.2 P0: 即実装（Must Have）

#### F01: ログイン機能（簡易認証）

- Flask + SQLite ベースの簡易ログイン
- 自分専用Webアプリとしてパスワード保護
- セッション管理（Flask-Login）
- 将来: 外注担当者には権限制限付きアクセス

#### F02: 商品情報管理（CRUD + CSV）

- 商品名、ブランド、価格、仕入先URL、画像URL、説明文、在庫数、利益率を登録・一覧表示・編集
- **CSV インポート/エクスポート**（Googleスプレッドシート連携含む）
- 商品画像はURL管理（ローカル保存も対応）
- ブランド階層（high/medium/low）自動/手動タグ付け

#### F03: 出品テンプレート自動生成

- BUYMA出品に必要な項目をテンプレートベースで自動生成:
  - タイトル（ブランド名 + 商品名 + サイズ + 色 + 素材）
  - 説明文（テンプレート変数置換: `{{brand}}`, `{{price}}`, `{{material}}` 等）
  - 価格（利益計算結果から自動設定）
  - サイズ表
- **出力方式:** クリップボードコピー or CSV出力 or AutoFiller用JSON出力
- BUYMA出品フォームへの自動入力は Selenium AutoFiller で補助（規約リスクを回避する手動確認フロー付き）

**テンプレート例:**
```
【{{brand}}】{{productName}}
カラー: {{color}}
素材: {{material}}
サイズ: {{size}}
定価: ¥{{retailPrice}}
仕入れ国: {{sourceCountry}}
状態: 新品未使用・タグ付き
```

#### F04: 禁制品買付先チェックシステム

- 商品ごとに買付先が禁止対象か自動判定
- 国内→店舗のみ許可、公式サイト/メルカリ禁止
- 海外→店舗+オンライン許可
- 商品登録時・買付先選択時にリアルタイム警告表示

#### F05: 18日ルール + 決済別延長期限ダッシュボード

- 各注文の発送期限を可視化管理
- 注文日・期限日・残日数・延長可否を一覧表示
- 決済方法別の最大延長期限を自動算出

**期限警告レベル:**

| 残日数 | 表示 | アクション |
|--------|------|-----------|
| 7日以上 | 緑（正常） | なし |
| 3-6日 | 黄（注意） | 進捗確認 |
| 1-2日 | 赤（警告） | 延長申請または発送催促 |
| 0日以下 | 緊急（点滅） | 即時対応 |

#### F06: パートナー管理

| 管理項目 | 説明 | 重要度 |
|---------|------|--------|
| レスポンス速度 | 平均応答時間（分） | 高 |
| 信頼スコア | 実績ベースの信頼度（0-100%） | 高 |
| 対応地域 | 買付可能エリア | 中 |
| 得意ブランド | 専門分野 | 中 |
| 優先度 | high/medium/low | 中 |

**対応地域マスタ:**
- 国内: 東京・大阪・名古屋・愛知・沖縄
- 海外: ユーロ圏・米国・香港・豪州・中国

### 3.3 P1: 第2フェーズ（Should Have）

#### F07: 品出し進捗トラッカー

- 日次/月次の出品進捗をリアルタイム追跡
- 日次目標: 20品 / 月次目標: 600品
- 7日間平均、前月比較のトレンド表示

#### F08: キャッシュフロー予測

- 月次売上予測
- 入金予定額（今月中の確定着金）
- 未着金残高
- 着金予測: 国内=注文日+15日、海外=注文日+25日（中央値）

#### F09: ブランド階層別利益率ダッシュボード

| Tier | 平均利益率 | 推奨アクション |
|------|-----------|---------------|
| ハイブランド | 15-25% | 規制解除後強化 |
| ミドルブランド | 10-15% | 主力として継続 |
| ロングテール | 5-8% | 回転率重視 |

### 3.4 P2: 第3フェーズ（Nice to Have）

#### F10: 在庫＆価格チェック（仕入れ元スクレイピング）

- 仕入れ元URL（Amazon・楽天・ブランド公式海外等）を定期的にスクレイピング
- 現在価格・在庫状況の変動を検知してアラート表示
- **対象:** BUYMA以外の仕入れ元サイトのみ（BUYMA本体へのスクレイピングは最小限）
- Selenium + selenium-stealth で実装（既存コードベース活用）

#### F11: 人気度トラッキング

加重スコア計算式:

```
popularity_score = (sales_normalized × 0.4) + (inquiries_normalized × 0.3)
                 + (favorites_normalized × 0.2) + (views_normalized × 0.1)
```

#### F12: 買付先地域最適化レコメンド

商品の最安・最速買付先を推奨（ブランド×地域の過去実績に基づく）

#### F13: リピーター管理

- 顧客別購入履歴・お気に入り・購買パターン
- クーポン発行機能

## 6. 価格計算ロジック

### 6.1 利益計算式

```
commission_rate = (sourceType == 'domestic') ? 0.077 : 0.055
fees = sellingPrice × commission_rate + transferFee(220)
customsDuty = (sourceType == 'overseas') ? calcCustomsDuty(cifPrice, category) : 0
profit = sellingPrice - purchaseCost - fees - customsDuty
profitRate = profit / sellingPrice × 100
```

### 6.2 決済方法別延長期限計算

```
extensionMap = {
  'credit_card': 45,
  'rakuten_pay': 45,
  'd_pay': 25,
  'au_pay': 25,
  'paidy': 25,
  'bank_transfer': 90,
  'convenience': 90,
  'paypay': 90,
  'amazon_pay': 90,
}
extensionDeadline = orderDate + extensionMap[paymentMethod]
```

### 6.3 入金予定日計算

```
expectedPaymentDate = orderDate + (
  sourceType == 'domestic' ? 15 :
  sourceType == 'overseas' ? 25 :  // 中央値
  0
)
```
