# ターミナル出力表示の制約について

## 現状

Cursor AI の `run_terminal_cmd` ツールでは、コマンドの標準出力が表示されない制約があります。

## 制約を外せるか？

### 結論

**完全に外すことは難しい**ですが、**回避方法はいくつかあります**。

### 理由

1. **ツールの根本的な制約**: Cursor AI の `run_terminal_cmd` ツールは、WSL環境でコマンドを実行しますが、標準出力のストリーミングに制限があるようです
2. **環境の違い**: WSL環境内で直接実行すると正常に出力が表示されますが、ツール経由では表示されません
3. **ツールの設計**: これは Cursor AI 側の設計による制約の可能性があります

### 確認したこと

以下の方法を試しましたが、出力が表示されませんでした：

1. ✅ `tee` コマンドでファイルにリダイレクト → 実行は成功、但し出力は表示されない
2. ✅ `bash -c` でラップ → 実行は成功、但し出力は表示されない
3. ✅ 環境変数を設定 → 実行は成功、但し出力は表示されない
4. ✅ 一時ファイルに出力 → ファイルは作成されるが、内容は表示されない

## 回避方法

### 方法1: ヘルパースクリプトを使用（新規作成）

`tools/run_test_with_output.py` を作成しました。このスクリプトは：

- テストを実行し、出力をファイルに保存
- 最新のテスト結果ファイルのパスを表示
- WSL環境に直接ログインして実行すると、出力が表示される

**使用方法**:

最も簡単な方法：Cursor のターミナルを使う

1. Cursor で `Ctrl + `` （バッククォート）でターミナルを開く
2. 自動的に WSL 環境に入ります（`.cursor/settings.json` で設定済み）
3. コマンドを実行：
   ```bash
   cd /home/yn441611/atelier-kyo-manager
   source venv/bin/activate
   python -m pytest tests/test_product_extractor.py -v
   ```

または、Windows PowerShell から：

1. Windows PowerShell を開く
2. `wsl` コマンドを実行
3. WSL環境に入ったら、上記と同じコマンドを実行

詳細は `docs/reports/WSL_LOGIN_EXPLANATION.md` を参照してください。

### 方法2: テスト結果ファイルを確認（既存機能）

`conftest.py` により、テスト結果は自動的に保存されています：

```bash
# 最新のテスト結果ファイルを確認
ls -lt docs/reports/TEST_RESULTS_*.txt | head -1 | xargs cat
```

### 方法3: WSL環境に直接ログイン

最も確実な方法は、WSL環境に直接ログインすることです：

```bash
# Windows PowerShell または CMD から
wsl

# WSL環境内で
cd /home/yn441611/atelier-kyo-manager
source venv/bin/activate
python -m pytest tests/test_product_extractor.py -v
```

この方法では、出力が正常に表示されます。

### 方法4: 既存のヘルパースクリプトを拡張

既存の `tools/run_with_summary.py` を参考に、テスト実行用のスクリプトを拡張することもできます。

## 推奨される解決策

### 短期的な解決策

1. **WSL環境に直接ログイン**してテストを実行（方法3）
   - 最も確実で、出力が正常に表示されます

2. **テスト結果ファイルを確認**（方法2）
   - `conftest.py` により自動的に保存されているため、確認が簡単です

### 長期的な解決策

1. **ヘルパースクリプトの改善**
   - `tools/run_test_with_output.py` を改善し、より使いやすくする

2. **CI/CD環境の活用**
   - テストは自動的に実行され、結果がファイルに保存される
   - ブラウザやIDEから結果を確認できる

## まとめ

**制約を完全に外すことは難しい**ですが、以下の方法で回避できます：

1. ✅ WSL環境に直接ログイン（最も確実）
2. ✅ テスト結果ファイルを確認（既存機能を活用）
3. ✅ ヘルパースクリプトを使用（今後改善可能）

**重要なポイント**：
- コマンドは正常に実行されています（exit code 0）
- テスト結果はファイルに保存されています
- WSL環境自体には問題はありません
- 制約は Cursor AI のツール側にあります
